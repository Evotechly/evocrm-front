# Shoogle MCP engineering selection — F2

PASS: `search_registry_items` executed for dashboard, sidebar, kanban, command, drawer, dialog, popover, input, select, date, filter, chart, timeline, toast and data-table. Initial concurrent calls hit service rate limits; retried sequentially at >2 seconds. A scoped query for `shadcn` returned `unknownRegistries: ["shadcn"]`, not a successful official-registry result. Raw responses: `shoogle-mcp-results.json`.

The available MCP exposes name search and installation arguments, not source retrieval. Source JSON and original licenses were therefore fetched from the returned registry and upstream GitHub. Do not imply that source retrieval used a nonexistent Shoogle tool.

## Original application first

Read EvoCRM package.json, CreateDrawer, command-palette compatibility export and PipelineKanban at main. Production already uses Radix dialog/popover/tooltip, cmdk, TanStack Table, native pipeline drag, Phosphor and Geist. Production source was read via GitHub only; never edited. The existing foundation table is a small semantic shell; with five records, a full table engine is not needed. Keep its data contracts and augment the composition with local filter/sort/pagination/selection controls.

## Security and measured impact

`pnpm audit` after the Vitest 5.0.2 patch reports zero advisories; machine output is in docs/certification/dependency-audit.json. Direct resolved versions/licenses are recorded in dependencies.json. Final production assets are approximately 476 kB JS (144.5 kB gzip) and 52.5 kB CSS (11.2 kB gzip), plus self-hosted fonts. This is aggregate measured cost, not an invented per-library benchmark. Test-only axe and Vitest are excluded from runtime. No runtime Motion, Next, lucide, large chart or table engine was added. Native controls keep dependency and bundle cost low.
